# nem-bess-formula-workbench

協助儲能（BESS）在澳洲 NEM NSW1 區域做充放電決策與收益評估的**公式工作台**。頁面列出幾條建議公式，公式本身、公式裡的輸入資料與權重都能由使用者自行設計與調整，畫面即時算出調整後的結果；每條公式旁邊說明原則、方法、建議怎麼選，以及來源。

**直接使用：[公式工作台](https://ancpower.github.io/nem-bess-formula-workbench/)**。不需要安裝、帳號或在本機執行專案，用瀏覽器打開就能用；你調整的式子與數值只存在自己的畫面上，不會影響別人。

## v1：使用者能拿它做什麼

v1 是目前已合併功能的版本，仍在收尾驗收；「已合併」不等於所有正式站項目均已驗收。逐項狀態與所有版本的可驗收目標只看 [requirements.md](docs/requirements.md)。

| 使用者的業務問題 | 可以操作什麼、得到什麼 | 判讀邊界 |
|---|---|---|
| 這段預調度期間有哪些充放電機會、要執行還是等待？ | 讀取 NSW1 預調度價格，查看排程與均價，設定最多 1 或 2 循環，逐循環看價差、淨收益與執行判斷 | 次數上限以整段預調度範圍計，不是每日。現有選窗分數未納入損耗與門檻，不保證是自訂規則下最好的可執行計畫 |
| 成本、效率或判斷公式不同，試算結果差多少？ | 修改數值、權重與公式，即時計算；還原設定或與預設值比較 | 公式求值會更新，但目前選窗未完整依自訂公式評分；不能把結果變化都解讀成已重新找到最佳窗口 |
| AEMO 讀取失敗時，我能否自行試算？ | 手動輸入充電與放電均價，看收益與判斷 | 明示手動試算，不冒充即時建議；手動均價只試算循環 1 |
| 現行價差標準，過去保留了多少收益、錯過哪些日子？ | 選歷史期間與門檻，查看保留率、執行天數及錯失收益 | 歷史只用固定單循環摘要；改效率或損耗沿用原窗口，不是重新最佳化。沒有預測誤差，不提供建議上調 |
| 目標期間收益在不同假設下大概多少？ | 手動輸入每日收益，或從歷史期間選 P10／P50／P90，再調天數、可用率及因素權重 | 歷史模式用設定檔設備與建議公式，不採卡片臨時改寫；分位數是每日收益分布，不是預測或超越機率 |
| 如何讓同事檢查我的設定？ | 複製分享網址，還原數值、公式、歷史條件及使用者調整的循環上限 | 網址不保存電價或歷史摘要；不同時間開啟，結果可能不同 |

v1 已有的防錯設計包括：區分即時／手動／讀取中／失敗／可能過期，讀取失敗清除舊曲線；不完整歷史日排除而非當作零收益；分享設定整份驗證，不合法時不部分套用；樣本不足與季節限制明示。這些設計降低誤判風險，不代表結果可直接代替交易決策或現場控制。

## v2：修改規則後，重新找值得執行的排程

**狀態：規劃中，尚未實作或驗收。** v2 採方案 C「每個完整計畫用共用公式評分」，並發布完整 30 分鐘歷史價格序列。它不是只把原排程重算一次，而是重新比較做零次、一次、兩次以及不同時段的合法計畫。

| 使用者的業務問題 | v2 預計提供的功能 | 業務邏輯與限制 |
|---|---|---|
| 多做一次，收入是否足以抵銷增加的損耗？ | 比較零、單、雙循環的完整計畫，依指定目標選排程 | 例如單循環扣損耗後 A$70、雙循環 A$60，預設淨收益目標選單循環，不因雙循環扣成本前較高就選兩次 |
| 調高價差標準後，還有別的機會嗎？ | 重新找符合門檻的窗口，而非只過濾舊窗口 | 兩個價差 3 的小循環不達門檻 4，但價差 5 的大循環可以執行時，應找出大循環 |
| 成本、效率或公式改了，應改在哪些時段做？ | 相關參數、執行判斷與目標公式改動時重新選窗 | 指定一條計畫目標控制排序；其他分析公式不自動控制排程。無對應資料的規則仍須另加設計 |
| 每日最多一次與兩次，過去收益差多少？ | 用完整歷史價格逐日重選，比較排程、執行天數與收益分布 | 歷史每日從空電池開始、不跨午夜；預調度可跨午夜且上限以整段範圍計，兩者不是同一時間邊界 |
| 新策略與預設策略，差異真的是設定造成的嗎？ | 固定同一份價格，兩邊各自重選，顯示窗口、次數、分數與淨收益差異 | 不拿不同價格或共用其中一方窗口的結果冒充策略比較 |
| 新策略的歷史收益，如何用於情境評估？ | 從各日最佳計畫的執行淨收益取 P10／P50／P90 | 分位數不取任意目標分數；納入有效零收益日、排除缺資料日；仍是事後價格，不是當時能實現的預測收益 |

### v2 延伸哪些設計，避免使用者被結果誤導

| 可能的錯誤 | 預計防錯方式 |
|---|---|
| 改了成本或公式，排程仍按舊分數選 | 選窗、執行判斷、完整計畫評分共用公式引擎；相關設定改變即重選 |
| 沒有值得做的機會，卻硬排一個循環 | 空計畫也是正式選項；預設規則下無正收益可執行機會就不做 |
| 自訂目標分數被看成收入 | 分開顯示目標分數與 AUD 執行淨收益，不隱藏真正最佳化的目標 |
| 公式壞掉，被當成零收益或略過 | 關鍵公式錯誤明示失敗，不宣稱找到最佳；不暗加另一份判斷規則 |
| 缺價格、時段不連續，仍拼出一個排程 | 驗證資料完整性與時間連續性；缺資料日排除，不冒充零收益 |
| 改完設定後，前一次慢計算蓋掉新答案 | 計算綁定設定版本，舊工作不得覆蓋新結果；提供進度與取消 |
| 自訂公式後，仍套原來的門檻建議 | 自訂模式停用不再適用的保留率自動建議，保留結果比較 |
| 搜尋沒做完，卻把部分答案稱為最佳 | 未完成、取消或超限明示狀態，不偷換為未標示的近似搜尋 |
| 重開歷史分享時換了資料，卻以為重現原結果 | 記錄資料與設定版本；原資料不可取得時說明不能重現 |

v2 不包含部分充放電、非空初始電量、跨日電量延續、時變 MLF、預測誤差、輔助服務或全年循環壽命預算。每次啟動固定成本等規則，須先具備相應輸入與彙總能力，不能假設改一句公式就自動支援。

## 預設公式

| 公式 | 式子 | 分頁 |
|---|---|---|
| 價差 | `discharge_price - charge_price` | 兩頁共用 |
| 每循環淨收益 | `capacity_mwh * mlf * (rte * discharge_price - charge_price) - capacity_mwh * rte * degradation_cost` | 兩頁共用 |
| 執行或等待 | `and(spread >= spread_standard, cycle_net_revenue > 0)` | 預調度 |
| 因素調整倍數 | `(w_demand * idx_demand + w_supply * idx_supply + w_battery * idx_battery) / (w_demand + w_supply + w_battery)` | 情境評估 |
| 目標期間收益 | `days * availability * daily_revenue * factor_multiplier` | 情境評估 |

使用者可以：

- 直接在公式的中文名稱框框裡改數值或權重，所有用到它的公式一起更新；打字時即時預覽，結論列右側顯示「計算中…」與「已更新」。
- 按「改寫公式」，用中文名稱改寫式子；點下方的名稱框框插入名稱，打一個新的中文名稱就多一個輸入框。畫面上不出現英文代號。
- 一鍵還原單條公式或全部設定。

## 設計原則

- **骨幹與肌肉**：骨幹是式子解析器、計算引擎、資料轉接與卡片介面，很少變動；肌肉是公式與變數，全部寫在 `formulas/` 的 JSON 裡。新增公式只要多加一筆，不用改程式。
- **MVP 優先**：需求依 MoSCoW 排序，Must 全部完成才算 MVP。三個面向的需求表見 [`docs/requirements.md`](docs/requirements.md)。
- **單一來源**：設備參數與價差標準只放在 `config/`，兩個分頁都讀同一份。
- **不用 eval**：式子由白名單解析器求值，只支援數字、變數、運算子與列出的函式。

架構與公式格式見 [`docs/architecture.md`](docs/architecture.md)。

## 適用範圍（B5）

- **可以用**：海外的電能自由市場，例如 NEM。這類市場的收益來自低價充電、高價放電，頁面上的價差與淨收益公式直接適用；預設資料只有 NSW1。
- **台灣不能直接用**：台灣的儲能收益主要來自輔助服務（例如 dReg、E-dReg），不是電能套利，要改用輔助服務公式。這組公式還沒做（需求表 B6）。

## 資料

| 資料 | 來源 | 用在哪 |
|---|---|---|
| 30 分鐘實際與預調度電價 | AEMO NEM 資料儀表板背後的 API（允許跨網域讀取，沒有公開文件）；同一個回應的 `ACTUAL` 與 `FORECAST` 列 | 預調度分頁的電價與充放電排程圖、充放電均價 |
| 設備參數 | `config/battery.json` | 容量、功率、來回效率、損耗成本、MLF |

| 每日收益摘要（T6） | `data/daily_summary.json`，由 AEMO 公開歷史結算價產製 | 情境評估的分位數與價差標準檢討；目前涵蓋 2026-03-01～2026-08-30，最後一次手動產製在 2026-10-20 |

### 資料可信度（T8）

實際電價原始資料是 5 分鐘時段。曲線與拖曳均價都使用六個不同、齊全時段聚合的 30 分鐘均價（以 NEM 時段結束時間分桶），缺筆或不完整時段留空，不採整點／半點單點代替。資料列分開顯示原始筆數與完整 30 分鐘時段數，圖下列出這次回應的實際覆蓋範圍；三天時間軸不代表有三天實際資料。T8 使用最新原始 5 分鐘時段判斷時效，不使用最後一個聚合桶。

充放電價格框最多顯示小數兩位，未輸入不會把顯示值寫回計算；手動修改後才建立覆寫。金額共用千分位格式，歷史明細保留兩位、主要總額顯示整元。

預調度的「執行／等待」只在電價即時時才當作當下建議顯示：

| 狀態 | 什麼時候 | 結論列 |
|---|---|---|
| 即時 | 讀到電價、最後一個實際時段結束不到 35 分鐘、沒有手動改均價 | 執行／等待 |
| 手動試算 | 你改了「充電段均價」或「放電段均價」 | 「手動試算」，理由列寫試算結果 |
| 可能過期 | 最後一個實際時段結束超過 35 分鐘；頁面開著每分鐘重新判斷 | 「資料可能過期」與幾分鐘前，理由列寫試算結果 |
| 讀取中 | 正在向 AEMO 取價 | 「讀取中」，不給判斷 |
| 讀取失敗 | AEMO 回應錯誤 | 「讀取失敗」；清掉上一次的電價與曲線，不拿舊值判斷 |

資料時間以最後一個實際時段的結束時間為準（NEM 時間，固定 UTC+10）；沒有實際時段時，用第一個預測時段往前推 30 分鐘。AEMO API 讀取失敗時，可以直接在公式的「充電段均價」「放電段均價」框裡輸入，結論列會標成手動試算。排程圖下方的判斷也會加上「試算：」。

## 每日收益分位數（P8）

情境評估的「每日收益：依參考期間選擇分位數」讀取本 repo 已發布的歷史摘要，沿用設定檔設備、建議公式與原單循環窗口。選擇參考起訖日、價差標準與 P10／P50／P90，按「使用歷史分位數」才會帶入每日淨收益；預設 P50，僅載入摘要不會取代手動／預設值。

啟用後，變更參考日期、標準或分位數會更新情境收益。直接修改公式裡的每日淨收益就回到手動模式；再次按按鈕才切回歷史模式。「全部還原預設」也會離開歷史模式。設定只保留於本次頁面，不寫回設定檔。

分位數使用排序後 `(n - 1) × p` 的線性插值：P10 是較低收益，不是收益超越機率。分母包含有效但不執行的零收益日，缺資料日排除；畫面列出有效天數、排除日期及樣本／季節限制。歷史模式發生日期或樣本錯誤時，情境結果顯示錯誤，不靜默回退預設收益。事後價格不是預測，也不採用卡片臨時改寫的公式或設備值。

## 分享與比較（P7）

按「複製分享網址」會把目前的設定編進網址（`?s=`），對方打開就是同一組設定。網址保存：你改過的數值、改寫的公式、在公式裡新增的中文名稱，以及啟用中的歷史分位數條件（參考起訖日、價差標準、P10／P50／P90）。

網址**不保存電價或歷史摘要**。預調度結果會依對方開啟當下取得的 AEMO 電價重算，可能與分享時不同；要對照同一時點的結果，請同時附上截圖或時間。分享內容整份驗證後才套用，有任何一欄不合格就用預設值開啟並顯示原因。「全部還原預設」會清除設定並從網址移除分享參數。

「與預設值比較」在同一份當次資料下計算預設版（沒有任何調整、不用歷史模式）與你的版本，逐條列出結果與差異；沒有調整時顯示「目前與預設相同」。

要新增或修改公式、設定、程式或文件，或要每月更新、重新產製歷史資料時，先看[專案地圖](docs/repo-map.md)：它列出每個檔案的用途、怎麼改、多常改，以及改了要一起更新哪些地方。特別是改公式登記檔、變數目錄或設備參數時，必須同時重產歷史摘要，否則情境評估分頁的歷史區會停用。只用瀏覽器使用工作台時不需要讀。

## 本機執行

頁面用 ES module，要經過 HTTP 才能開：

```bash
python3 -m http.server 8000
```

然後開 [本機工作台](http://127.0.0.1:8000)。

## 測試

需要 Node 22 以上，沒有 npm 依賴：

```bash
node --test "tests/*.test.js"
```

測試涵蓋式子解析、計算引擎、分享網址編碼與驗證、預設版比較、資料時效與可信度、公式登記檔格式檢查（每條公式都必須有原則、方法、建議與至少一個 https 來源）、預調度選窗、電價曲線資料、排程圖刻度抽稀、中文式子轉換與介面互動。CI 在每個 PR 執行。
